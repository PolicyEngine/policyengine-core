`set_input_divide_by_period` and `set_input_dispatch_by_period` now leave only inputs in place when they spread a longer period's input over a variable's months or years: a value the simulation calculated for a sub-period (a default, a formula result) is replaced, and the variable's values it calculated over an overlapping period (a sum, a twelfth) are dropped, so the same input gives the same values whatever was calculated before it was set (previously a calculated month kept its value and changed the others' share, or made the input fail as inconsistent). `dump_simulation` records which values were inputs and `restore_simulation` restores exactly those as inputs, so a restored simulation's inputs keep counting as inputs.
